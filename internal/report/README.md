# report — what was found, and what it cost

Two outputs, both free, both printed rather than generated by a model.

## `Report` — the summary

Everything known so far in one page: the flow, the findings by severity, what round
one settled, the test plan, and the token ledger. It is the answer to "what does
testigo currently think about this repository", and it costs nothing to ask.

## `Measure` — the token ledger

Reads the bytes actually written to `testigo/asks/` and read back from
`testigo/answers/` and reports them:

```
  prompts sent        14.7k across 9 prompt(s)
  read back            2.8k across 9 answer(s)
```

This is **measured, not estimated** — it is the size of files on disk. The planner's
figure before a run is a forecast; this is the receipt. Keeping the two separate is
deliberate, because a forecast that quietly becomes the historical record is how cost
tracking stops being trustworthy.

It deliberately reports tokens and not currency. Prices change per model and per
vendor, and a number in dollars would be stale and wrong in a way a token count is
not.

## `Flowchart` and `StateDiagram` — Mermaid

The flow as a diagram, and one diagram per detected state machine. Rendered as text,
so it goes in a pull request, a wiki, or a terminal, and diffs like code.

## The agent-written report

`testigo report --ask` writes a prompt instead, and the agent produces
`testigo/REPORT.md`: one coherent document covering the flow and its types, the
scenarios and techniques that ran, the results, the weak and strong spots, and every
detected problem with its `file:line` and a fix.

The prompt binds the fix: it must be safe for money. Nothing that could charge twice,
drop a payment or lose the audit trail. A database constraint beats a check in Go,
and the cost of the fix has to be stated so a reader can decline it.
